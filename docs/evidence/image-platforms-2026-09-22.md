# Rendered image platform check (2026-09-22)

`ops/check-images` rendered the regtest and testnet LND charts with monitoring enabled plus the vendored monitoring chart. It found 12 distinct image references, including the operator-injected Prometheus config reloader argument. Every rendered reference carried a pinned digest present in `ops/images.lock.json`.

For all 12 rendered lock entries, `skopeo inspect --raw` returned the expected OCI index digest and both `linux/arm64` and `linux/amd64` manifests. A run using the same pinned Linux Helm container wrapper as CI also passed. The collector's pinned Python base is now a thirteenth lock entry, and a subsequent `ops/check-images` run verified its Dockerfile reference, OCI index digest, and both target manifests. This check inspects manifests and does not pull image layers. The Mac arm64 runtime images used by the wallet-free stack were pulled and started during the separate full clean bootstrap.

The project-owned payment collector image was subsequently built for Mac linux/arm64, loaded into K3s, and built with Buildx `--output type=cacheonly` for linux/amd64 and linux/arm64. Then the pinned Python base's amd64 variant was copied from the locked OCI index into local Docker. Buildx built and loaded the collector from the same source for `linux/amd64`; `docker run --platform linux/amd64` reported `x86_64` and imported `payment_metrics.py` successfully on the Mac Docker engine. The arm64 image likewise reported `aarch64` and imported the module. These checks prove both image variants can start under Docker Desktop on the Mac; the Windows K3s runtime and live LND sidecar checks remain pending.
