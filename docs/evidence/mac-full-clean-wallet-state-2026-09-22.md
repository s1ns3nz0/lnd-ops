# Mac full clean bootstrap with wallet-state monitoring (2026-09-22)

Scope: Mac arm64, wallet-free infrastructure and synthetic alert delivery. This is not the funded-node or Windows MVP exit proof.

1. Before cleanup, `ops/verify regtest` and `ops/verify testnet` reached their manual wallet gates, and direct `kubectl exec ... test ! -e wallet.db` checks succeeded for both regtest LND Pods and the testnet LND Pod. The cluster contained only Kubernetes system namespaces plus `lnd-regtest`, `lnd-testnet`, and `lnd-monitoring`. Its five PVCs belonged to those project namespaces.
2. Ran `ops/reset-disposable regtest --confirm-unfunded`, `ops/reset-disposable testnet --confirm-unfunded`, and `kubectl delete namespace lnd-monitoring --wait=true`. Confirmed only system namespaces remained and `kubectl get pvc -A` reported no resources. Stopped and deleted the `lnd-ops-k3s` Lima VM. Removed all four `localhost/lnd-ops-payment-collector` tags from the host Docker image store. `limactl list` reported no instance and the host had no project collector tag. The Lima Ubuntu download cache and Docker Buildx layers remained.
3. From VM absence, `ops/doctor` passed with a warning that the old kubeconfig could not reach a cluster. `ops/check-images` rendered 12 pinned image references plus the Python collector base and verified that each locked OCI index offered linux/arm64 and linux/amd64 variants. `ops/bootstrap` recreated the VM and K3s v1.36.4+k3s1, reported Secret encryption enabled, and waited for the node to become Ready. A second `ops/doctor` passed. The new K3s image store had no collector image before `ops/build-collector`.
4. Ran `ops/deploy regtest` and `ops/deploy testnet` from namespace absence. The two releases installed as revision 1. Bitcoin Core and three LND Pods were Running; their new Bound PVC UIDs were regtest Bitcoin `8ab2a0c4-67f8-4e05-8892-2f595a18b89c`, regtest lnd-0 `dc34b155-7fb9-43d6-b799-b5ce523036d7`, regtest lnd-1 `e14c7e1f-6d08-4e0b-92a6-2a13ed710872`, and testnet lnd-0 `73a26041-e600-4e9b-9277-3a9fd9f79e93`. Both `ops/verify` commands passed infrastructure checks and exited `10` at the manual wallet gate. The K3s API listener on the Mac was `127.0.0.1:6443`.
5. Ran `ops/deploy-monitoring` from namespace absence. All six monitoring Pods became Running, its new Prometheus PVC was Bound with UID `67f6fa1d-e50b-41b2-94e5-e2f35116e323`, and `ops/verify-monitoring --infrastructure-only` passed. Prometheus reported eight healthy project rules and the `/wallet-state` scrape job. Grafana's authenticated API returned all four project dashboards with 8, 8, 10, and 4 panels; the Overview included wallet/RPC state. `ops/build-collector` built the current arm64 source image `localhost/lnd-ops-payment-collector:8221630d886cdeac` from no host project tag and imported it into the new K3s image store.
6. `ops/deploy regtest --monitoring` and `ops/deploy testnet --monitoring` each exited `10` before Helm mutation because no wallet/read-only macaroon existed; both LND releases stayed at revision 1. `ops/verify-monitoring --profile regtest` also exited `10` at the wallet and live scrape gate. On the freshly created monitoring stack, `ops/test-lnd-alerts --wallet-locked` reached Alertmanager, confirmed suppression of dependent alerts with lndmon up, and removed its fixture Pod, Service, and NetworkPolicy.

The clean run proves the current wallet-free Mac infrastructure and synthetic wallet alert path can be recreated after project VM, namespace, PVC, K3s image-store, and host project-image removal. It does not prove wallet creation, channel/payment operation, SCB recovery, live LND monitoring, funded redeployment, full Docker build-cache removal, or any Windows runtime behavior.
