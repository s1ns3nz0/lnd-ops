# Mac testnet empty-wallet smoke test (2026-09-22)

`ops/deploy testnet` installed the same chart with its Neutrino profile in a separate `lnd-testnet` namespace. Its single LND Pod reached Running and its 30 GiB PVC Bound. `ops/verify testnet` passed infrastructure checks and exited `10` with a wallet-creation action. No testnet wallet was created or funded. After confirming `wallet.db` was absent, the entire namespace and PVC were deleted. This is a smoke test, not the stage 3 sync, channel, payment, SCB, or clean-start exit check.

Later in the same Mac session, `ops/reset-disposable testnet --confirm-unfunded` checked that the testnet Pod and data directory were inspectable and that `wallet.db` was absent, then deleted the entire `lnd-testnet` namespace and PVC. `ops/deploy testnet` recreated the namespace, chart revision 1, Running LND Pod, and Bound 30 GiB PVC with UID `0457e4ea-cc2a-4ee9-a0f0-8368d8a0db6a`. `ops/verify testnet` passed infrastructure checks and exited `10` at the documented manual wallet gate. A second `ops/deploy testnet` upgraded the release to revision 2 and preserved the same PVC UID. This proves the wallet-free testnet resource reset and repeat deployment on Mac; it does not prove a synced, funded, monitored node or the Windows run.

A review found that the reset script had treated any failed `kubectl exec ... test -f wallet.db` as proof of absence. Changed it to require a successful `kubectl exec ... test ! -e wallet.db` before deletion. The repository test `tests/reset-disposable.test.mjs` forces that absence check to fail and confirms exit `1` without a namespace delete call; `npm test` passed all four tests. The live wallet-free testnet namespace was then deleted again with the revised script and recreated by `ops/deploy testnet`; the new LND Pod was Running and PVC UID `58d9f97a-f2b9-472f-93cc-f3b975a7520d` was Bound. `ops/verify testnet` passed infrastructure checks and exited `10` at the wallet gate.
